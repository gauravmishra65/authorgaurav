## 3. Link inventory

`scripts/validate-links.mjs` (new this pass) scans every pre-rendered page in `dist/` and classifies every `href`/`src`. Current counts against the 29-route build:

- **29 pages scanned**, **0 failures**, **1,130 warnings** (all one category — see below).
- Every internal route resolves to a real `dist/<route>/index.html`; every internal asset link resolves to a real file.
- Every page's canonical tag, `og:url`, and sitemap entry agree exactly (trailing-slash form).
- The 1,130 warnings are all `non-trailing-slash-internal-link`: `<Link>`/`<a>` elements using React Router client-side navigation (e.g. `to="/books"` instead of `to="/books/"`). These never cause a broken experience for a real visitor (React Router intercepts the click; no server round-trip happens), but they do mean a crawler following the raw `href` would take one extra 301 hop before reaching the direct-200 URL. Documented as a known, non-blocking inefficiency rather than silently ignored or mechanically patched across ~20 files in this pass — flagged for future cleanup, not treated as fixed.

Full detail: `reports/link-validation-report.md` / `.json` (regenerated on every `npm run validate:links`; gitignored, not shipped as a permanent artifact).

## 4. Broken links found / fixed / hidden

**Found and fixed (real bugs, not noise):**

1. **Contact page dead "YouTube" link** (`src/pages/Contact.tsx`) — rendered an unfiltered `href="#"` pill because it iterated `socialLinks` directly instead of the already-existing `getVerifiedSocialLinks()` filter used elsewhere. Fixed by centralizing the filter so this class of bug (forgotten filter at one of several call sites) can't recur — see `src/data/social.ts`.
2. **Social-share links baked to `localhost:4174`** (`src/components/SocialShareButtons.tsx`) — the pre-render pipeline runs a real headless browser against `vite preview` on localhost; the component built its share URL from `window.location.origin`, so every static "Share on Facebook/X/WhatsApp/LinkedIn" link shipped to production pointed at localhost until client-side hydration silently corrected it. Fixed to always use the real `SITE_URL` regardless of render environment.
3. **Three bare-domain (non-trailing-slash) URLs in `index.html`** (`og:url`, Person JSON-LD, WebSite JSON-LD) — now consistent with the sitemap's trailing-slash convention.
4. **`BlogPostDetail.tsx` building its own canonical/breadcrumb URLs by hand**, missing the trailing slash and duplicating logic already centralized in `src/lib/url.ts` — now uses the shared helper.

**Hidden (correctly, not fabricated):**

- *A Journey of Grace* shows **zero** purchase links anywhere (no `#`, no "Coming Soon" fake CTA) — verified live via Playwright (`e2e/smoke.spec.ts`'s dedicated test) because no real retailer URL exists in the database.
- The YouTube social link stays out of every rendered page (never a dead `#` pill) via `getVerifiedSocialLinks()`.

## 9. Accessibility results

`e2e/accessibility.spec.ts` (new this pass, using `@axe-core/playwright`) against all 24 major routes:

- **Final: 0 critical, 0 serious, 0 moderate, 0 minor** violations, sitewide.
- This was reached after finding and fixing real, verified issues, not by loosening the check:
  - `link-in-text-block` — mailto: links on 3 legal pages distinguishable only by color, not underline.
  - `color-contrast` (the largest category) — `.btn-gold-outline`'s text color measured ~3:1 against its typical light background (needed 4.5:1); root-caused to one shared CSS rule using the wrong of two existing gold tokens, fixed in one place (`src/index.css`), with inline overrides for its 3 legitimate dark-background uses. Also found and fixed: Shadow Code's dark-section eyebrow caption (its own red accent measured ~3:1 against the site's navy), Offbeat Love's entire theme accent color (~2.7:1 against its own theme surface — fixed at the theme-definition level in `bookThemes.ts` so it cascades to every usage), the sitewide `rose` color token used for every form-validation error message (~4.4:1, just under threshold — darkened slightly), and an `opacity-70` on a Contact-form hint that dragged an otherwise-fine color below threshold.
  - `aria-hidden-focus` — the homepage's infinite-scroll book carousel marks its duplicated (looped) half `aria-hidden="true"` but it still contained real, tabbable links — a genuine broken-focus-order bug for keyboard/screen-reader users, fixed with `inert`.
  - `region` — the site-wide announcement bar rendered outside any landmark region; given an explicit `role="region"`.
  - `heading-order` — Writing Resources page jumped from `<h1>` straight to `<h3>`, skipping `<h2>`; fixed.
- Full detail: `docs/accessibility-test-results.md` (regenerated on every `npm run test:e2e -- accessibility`).
