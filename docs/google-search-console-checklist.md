# Google Search Console Checklist (Owner Action Required)

This entire checklist requires access to the real Google account that owns (or will own) `authorgaurav.com` in Search Console. None of it can be done from this codebase or by an engineering session — Search Console has no API a script can safely act through on your behalf for verification/submission, and doing so would mean handling your Google credentials, which is against project policy. Work through these in order.

## 1. Verify the domain property

1. Go to [Google Search Console](https://search.google.com/search-console) and sign in with the Google account that should own this property.
2. Add a property for `authorgaurav.com` — use the **Domain** property type (not "URL prefix") so it covers `https://authorgaurav.com` and any `www.` variant under one property.
3. Verify ownership via **DNS TXT record** (the recommended method for a Domain property): Search Console gives you a TXT record value; add it at your domain registrar's DNS settings (wherever `authorgaurav.com`'s DNS is managed — check the GitHub Pages custom-domain setup docs from earlier in this project if you need the registrar name).
4. Wait for DNS propagation (can take a few minutes to 48 hours), then click **Verify** in Search Console.

## 2. Submit the sitemap

1. Once verified, in the left sidebar go to **Sitemaps**.
2. Enter `sitemap.xml` (resolves to `https://authorgaurav.com/sitemap.xml`, auto-generated by `scripts/generate-sitemap.mjs` on every build) and click **Submit**.
3. Confirm the status shows "Success" after Google fetches it (may take a few hours). It should report the site's ~29 URLs (static pages + book pages + blog posts).

## 3. Request indexing for key pages

Google will discover pages from the sitemap on its own schedule, but you can nudge the important ones sooner:

1. Use the **URL Inspection** tool (search bar at the top of Search Console) for each of these:
   - `https://authorgaurav.com/`
   - `https://authorgaurav.com/books/`
   - `https://authorgaurav.com/books/the-shadow-code/`
   - `https://authorgaurav.com/books/offbeat-love/`
   - `https://authorgaurav.com/about/`
2. For each, if it shows "URL is not on Google," click **Request Indexing**. This queues a crawl — it isn't instant, and Google may still take its own time.
3. Do **not** repeat this for every single page on the site in one sitting — Search Console rate-limits indexing requests, and it isn't necessary since the sitemap covers everything.

## 4. Confirm canonical and mobile usability

1. In the **URL Inspection** results for a couple of pages above, check the "Coverage" section confirms the canonical URL Google selected matches the page's own `<link rel="canonical">` tag (this project's `src/lib/url.ts`/`Seo.tsx` already keep canonical, sitemap, and og:url in agreement — see `docs/accessibility-test-results.md` and the link-validation report for the verified state as of this pass).
2. Check the **Mobile Usability** report (under Experience) after the site has been crawled a few times — it should show no errors, given the site has already been tested at 320px+ viewports.

## 5. Ongoing hygiene

- **Do not repeatedly change page titles/meta descriptions** once indexed — frequent metadata churn can slow down how Google treats the page's ranking signals. Make deliberate changes, not iterative tweaks.
- **Allow time for recrawling** after any real content change — don't judge whether a change "worked" by checking Search Console the same day.
- Revisit the **Sitemaps** report after each deploy that adds a new book or blog post, to confirm the updated sitemap was picked up (it's regenerated automatically pre-build, so no manual resubmission is needed unless Google's own re-fetch seems stuck).
- The **Performance** report (clicks/impressions/average position) only starts populating a few days after verification — nothing to check immediately.

## What's already handled by the codebase (nothing to do here)

- `sitemap.xml` generation, trailing-slash canonical normalization, and pre-rendered static HTML for every public route are already built and verified (see `scripts/generate-sitemap.mjs`, `src/lib/url.ts`, `scripts/prerender.mjs`, and `reports/link-validation-report.md`).
- `robots.txt` already exists at `public/robots.txt` and references the sitemap.
